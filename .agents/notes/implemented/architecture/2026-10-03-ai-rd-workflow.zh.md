# Agent Note: Harness 中叠加式本地研发流程

Status: implemented

[English](2026-10-03-ai-rd-workflow.md) | 中文

## Problem

本地试运行需要持久化需求、评审和测试决策，并复用 Harness 的模型、会话与工具执行。助手文本不能授权范围冻结或生产发布。

## Decision

[研发包](../../../../packages/rd/README.zh.md)通过叠加式本地配置组合。事务性的 SQLite 项目聚合保存业务记录；成员凭据、命令回执和会话关联使用独立表。命令重新读取成员权限，检查上下文与项目修订后再应用生命周期规则。

需求修订、材料和基线保留不可变引用。技术评审绑定已审阅材料；开发评审绑定完整候选提交。每次提测保存独立用例、缺陷和产品 UAT。发布命令仅记录外部证据，不执行部署。

成员的 Harness 会话固定需求、版本、基线和任务。产品会话获得限定范围的起草工具。源码工具要求明确绑定规范化工作区、分支、冻结基线、任务负责人和单工作区写入锁。基线变更等待智能体与进程停止。

工作流将已提交记录导出为数据库同级的 Markdown。不可变产物文件保留每次提交修订，版本与阶段索引展示当前状态。SQLite 仍负责事务，因此文件错误可基于已提交的命令回执恢复，不必重复执行操作。导出文件的手工编辑不会导回业务记录。

研发面板持有标准 Session 引用并嵌入共享 Conversation 渲染器，复用原生思考过程、工具展示和流处理，不再维护另一套会话文本投影。独立输入框通过限定业务上下文的检查提交请求。业务上下文以单独记录的 `rd-context` 消息传入，让用户请求保持可读。

## Alternatives considered

修改核心 Agent Loop 会让业务审批耦合上游模型执行。叠加的工作流服务让业务状态独立。按功能拆分规范化数据表可提供更细并发；单本地项目聚合简化当前未发布试运行的事务，代价是较保守的冲突判断。

## Consequences

一套部署对应一个本地项目，一个候选提交对应一个仓库。主机管理员与标准 Harness 管理能力属于受信任主体。成员权限保护业务命令，不隔离共享主机上的恶意租户。项目级乐观锁可能拒绝无关并发修改。企业身份、远程执行、多仓库清单和自动发布集成不在本期范围。
