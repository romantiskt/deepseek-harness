# AI 研发工作台：本地试运行指南

[English](ai-rd-pilot.md) | 中文

本教程在可信本机启动工作台，并演示一个版本的主线操作。一套部署对应一个项目。

<a id="start"></a>
## 1. 启动工作台

使用 Node 22.23.1 或根目录清单允许的兼容版本，以及锁定的 pnpm 11.7.0。在当前仓库运行以下命令。完整构建包含上游主机与浏览器，首次构建需预留足够内存。

```sh
pnpm install --frozen-lockfile
NODE_OPTIONS=--max-old-space-size=12288 pnpm run build:rd
pnpm run dev:rd
```

打开终端打印的私密初始化链接。服务监听 `http://127.0.0.1:3091`；`AI_RD_PORT` 可修改端口。初始化令牌需保密。启动器通过官方 CLI 创建 `ai-rd` 配置并链接本地 bundle。

默认数据目录为 `.local/harness-home`，显式设置 `DSH_HOME` 可选择其他目录。业务状态位于 `rd/workflow.sqlite`；Harness 管理会话日志、模型设置和凭据。此目录已由 Git 忽略。

<a id="members"></a>
## 2. 创建成员并选择模型

首次使用时创建本地管理员，密码至少 12 位。管理员添加产品、开发和测试账号。各成员使用自己的账号登录，角色由服务端管理。通过 Harness 设置配置可用模型与凭据。

当前仓库已有隔离验收项目。测试账号保存在私密权限的 `.local/pilot-access.json` 中，仅为本地测试身份，不是企业账号。不要公开该文件。

本地管理员账号是该文件顶层的 `username`，密码是对应的 `password`；`members` 内保存产品、研发和测试的独立账号。显示“登录研发空间”时需要已有账号，不能在此创建新成员。账号或密码不匹配会保留输入并提示核对；会话超过 12 小时后需要重新登录。

<a id="workflow"></a>
## 3. 完成一个版本

阶段栏只切换查看内容；只有明确的业务操作才能推进流程。AI 对话保持可见，旁边提供节点、产物与活动面板。

1. 创建版本。与 AI 讨论需求，编辑结构化草稿，再保存到需求池或当前版本。需求评审与加入版本是独立操作。
2. 记录影响分析与技术方案。开发评审技术方案，测试评审用例，产品评审交互。安全评审可说明原因后标为不适用。产品冻结已评审范围；技术材料修改会重新打开技术评审。
3. 创建开发任务。负责人登记本地 Git 仓库绝对路径和当前分支，再绑定工作区。首次 AI 开发会话需要干净工作区。开始开发对话前需明确选择任务。
4. 让 AI 读取和修改选定源码。既有文件必须先读后写；外部编辑会阻止覆盖。查看差异并明确执行 npm test/build/lint 检查。可停止和继续；停止不会标记任务完成。
5. 在终端审阅并提交候选代码，平台不自动提交或推送。完成任务后，以同一个完整提交 SHA 记录自测、代码评审、CI 和联调证据。提测要求该提交是干净工作区当前 HEAD，并提供制品、环境和自测报告。
6. 测试记录用例和缺陷。测试失败返回开发。登记修复提交、重新确认候选评审后创建新批次。在新批次回归缺陷，旧结果不会沿用。测试准出要求用例通过、缺陷关闭。产品独立记录 UAT；UAT 驳回会返回开发并要求新批次。
7. 产品批准发布准入。记录实际外部制品、灰度、分析、全量发布与验证。平台仅保存证据，不执行部署。补充效果分析、回流需求、复盘和知识后关闭版本。关闭的版本不能重新发布。

<a id="changes"></a>
## 4. 处理需求变更

通过底部变更入口填写新需求正文、验收标准和影响节点。待审批变更暂停相关写入。批准后保留旧基线与产物，重新打开受影响评审和下游交付，并暂停任务。未受影响的并行评审保留。重新评审、冻结新基线后，再明确绑定任务工作区。驳回保留原业务状态。

<a id="recovery"></a>
## 恢复参考

错误会显示在当前弹窗内。重试前应先核对最新状态。

- 修订冲突：刷新，检查最新文档后重试。网络结果不明时保留命令幂等键，重试不会重复执行已提交操作。
- 模型错误：修正 Harness 模型配置后重新发送。模型失败不会批准业务步骤。
- 工作区占用或 HEAD 变化：停止当前执行，检查差异，登记最新工作区事实后重新绑定。系统不会自动重置或清理文件。
- 重启：持久化记录和 Harness 会话保留；未提交源码保留在工作区。重新连接，必要时登录，再明确继续。旧基线会话仍保留在 Harness 会话历史中。
- 备份：停止主机后复制整个 Harness home。运行中的数据库需使用 SQLite 备份能力，不能在 WAL 活动时只复制主文件。

<a id="limits"></a>
## 试运行边界

这是可信本机试运行。业务角色不隔离拥有文件系统或标准 Harness 管理权限的恶意用户。一个候选对应一个仓库。企业 SSO、PMP、Gerrit、Jenkins、远程执行和自动发布属于二期。已验证与未验证范围见[验收记录](../acceptance/phase-1.zh.md)。

AI 编写的提交正文使用一个 `[AI-Generated]` 标记。新 Java/Kotlin 源码遵守用户要求的作者、日期、用途和邮件头；方法与字段添加简明用途注释。
